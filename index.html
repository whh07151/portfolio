손님 앱·사장 앱·POS가 하나의 주문 상태를 공유하는 그룹 점심 조율·주문 플랫폼입니다. 추천→투표→주문→결제→접수 흐름을 정의하고 데이터가 일부만 반영되거나 잘못된 순서로 변경되지 않도록 백엔드를 설계했습니다.

주요 담당

  • ERD·REST API·주문 상태 전이 설계 및 NestJS 백엔드 구현
  • PostgreSQL 트랜잭션/RPC 기반 주문 데이터 정합성 관리
  • Toss Payments·JWT·FCM·Gemini API 연동
  • AWS EC2 배포 및 운영 장애 대응

문제 해결 · 성과

  • 주문 생성 3개 작업을 하나의 트랜잭션으로 묶어 부분 반영 차단
  • 스키마 불일치의 무오류 빈 응답을 분석하고 마이그레이션 검증 규칙 수립
  • 네트워크 오류를 재시도 가능 여부로 분류하고 점증 백오프 적용
